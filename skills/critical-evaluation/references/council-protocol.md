# Council protocol (single-agent multi-lens)

Inspired by Karpathy-style stages and packaged council skills (five tension lenses, anonymized-style peer review, chairman). **All stages run in one model** unless the user runs multiple providers externally.

## Mandatory triggers (user language)

council this · run the council · war room · pressure-test · stress-test · debate this — when paired with a real decision.

## Stages

### 1. Frame

Decision · stakes · success · out of scope. One clarifying question only if unusable vague.

### 2. Five lenses (all required; keep each tight)

| Lens | Ends with |
|------|-----------|
| **Contrarian** | The question being avoided |
| **First principles** | A redrawn decision / right variable |
| **Expansionist** | A ceiling-raising option |
| **Outsider** | The confused-newcomer question |
| **Executor** | One Monday-morning step |

Each lens must include **≥1 failure risk**. No pure praise lens.

### 3. Peer-style review

Strongest lens · shared blind spot · contradictions.

### 4. Chairman

Agreements · clashes · recommendation · **one** next action · confidence · short pre-mortem.

### 5. Consensus attack (mandatory)

State the emerging recommendation in one sentence. Produce **one** sharp case **against that consensus** (not a soft early contrarian only). Then note whether the recommendation survives.

Why: soft role-framing at the start often fails to create real dissent; attacking the converged answer is the higher-leverage pattern described in multi-agent debate practice notes.

## Limits

Correlated errors; not multi-model independence. Prefer separate providers for high-stakes factual disputes.
